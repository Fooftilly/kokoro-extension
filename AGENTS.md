# AGENTS.md — Kokoro TTS Extension

Guidance for humans and coding agents working in this repository.

## Architecture / file map

| Path | Role |
| --- | --- |
| `background.js` | MV3 service worker / background scripts: context menus, API fetch, downloads, shortcuts, connection icon |
| `content.js` | Content script: selection/article extract, overlay injection, auto-scroll, floating mic |
| `popup.html` / `popup.js` / `popup.css` | Settings UI: API URL, voice mixer, stream/download, normalization toggles, theme |
| `overlay.html` / `overlay.js` / `overlay.css` | In-page TTS player overlay |
| `reader.html` / `reader.js` / `reader.css` | EPUB reader page |
| `text-processor.js` | Text normalization / pronunciation prep before TTS |
| `audio-manager.js` | Playback / streaming audio handling |
| `dom-utils.js`, `theme-init.js`, `transliteration-lite.js` | Shared helpers |
| `build.js` | Builds Chrome + Firefox packages under `dist/`, generates manifests |
| `tests/` | Jest unit tests (jsdom); Kokoro API is mocked |
| `icons/`, `assets/` | Icons and README screenshots / store badges |

## Source vs generated

- **Edit source** at the repo root (JS/HTML/CSS listed above) and `tests/`.
- **Do not edit** `dist/` — it is generated by `npm run build` / `npm run package` and is gitignored.
- Vendored library copies land in `dist/` from `node_modules` during build (polyfill, Readability, compromise, DOMPurify, epub.js, JSZip).

## Browsers and MV3

- Targets **Chrome** and **Firefox** Manifest V3.
- Chrome: `background.service_worker`; Firefox: `background.scripts` + polyfill + `browser_specific_settings.gecko`.
- Chrome limits default command shortcuts (EPUB shortcut has no suggested key on Chrome).
- Host permissions ship with localhost defaults; non-local APIs use **optional** host permissions requested at runtime — do **not** silently broaden permissions in PRs.

## Permissions / security

- Required permissions today: `contextMenus`, `storage`, `activeTab`, `notifications`, `scripting`, `alarms`, `downloads`.
- Default host permissions: `http://127.0.0.1/*`, `http://localhost/*`.
- Optional: `*://*/*` for user-configured remote/LAN endpoints.
- CSP for extension pages: `script-src 'self'; object-src 'self'`.
- **No telemetry** or analytics without explicit maintainer approval.
- Text/content is sent only to the **user-configured Kokoro-FastAPI endpoint** (localhost, LAN, or remote).

## Install / test / build / package

Canonical commands (Node **>= 20**):

```bash
npm ci                 # clean install from package-lock.json
npm test               # full Jest suite
npm run lint           # ESLint on source + tests
npm run build          # tests + write dist/chrome and dist/firefox
npm run package        # build + zip packages (Chrome zip + web-ext Firefox zip)
```

- Prefer `npm ci` over `npm install` for CI and agent clean installs.
- `package.json` `version` is the **single source of truth**; `build.js` reads it for manifests and zip names. Do not bump the public extension version for housekeeping alone.

## Regression expectations before a PR

1. Add or update **targeted Jest tests** for the changed behavior.
2. Run `npm test` (full suite).
3. Run `npm run lint` if lint is in scope.
4. Run `npm run build` and confirm `dist/chrome/manifest.json` and `dist/firefox/manifest.json` exist and look correct.
5. Do not commit `dist/` or edit generated files by hand.

## Mocked Kokoro vs real / manual

- Unit tests **mock** `fetch` / storage / browser APIs — a live Kokoro-FastAPI server is **not** required for `npm test` or `npm run build`.
- Manual / exploratory checks (voice list, streaming, remote host permissions) need a real Kokoro-FastAPI instance configured in the popup.

## Versioning / release

- Bump `package.json` `version` when cutting a store release; rebuild so manifests and package filenames match.
- Chrome and Firefox packages are produced by `npm run package`.
- Keep LICENSE (MIT) and `package.json` `license` aligned.

## Issue / PR workflow

- Prefer GitHub issues as the source of truth for bugs and tasks.
- One PR should deliver one bounded change set; link the issue(s).
- Search existing issues/PRs before opening duplicates.
- See `docs/agent-workflows/cursor-projects.md` for Cursor Project / worker conventions.

## Hard rules for agents

- Do not edit `dist/` directly.
- Do not introduce framework rewrites or unrelated architecture changes in bugfix PRs.
- Do not broaden permissions or host access without an explicit, reviewed reason.
- Do not add telemetry, analytics, or phone-home behavior without approval.
- Stop after two identical failed fix attempts and report blockers instead of looping.
