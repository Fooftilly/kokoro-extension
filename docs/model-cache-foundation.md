# Opt-in local model data cache (#55)

This is the first stage of a shared model manager for the separate MediaPipe and ONNX backends. It is not a complete download UI, not a model catalog, and not a working TTS engine.

The module model-data-store.js accepts an extension-shipped model manifest that declares a provider (mediapipe or onnx), a variant, a 40-character immutable Hugging Face model revision SHA, and the **complete set of data assets**, each with a path, pinned HTTPS URL, exact byte size and a SHA-256 Subresource Integrity value (base64). It rejects unpinned URLs, invalid sizes, duplicate paths, unrecognized providers, and missing integrity values.

Calling status() does not download anything. Calling install() explicitly makes CORS fetches with the browser's SRI-integrity option and AbortSignal and streams each response into extension-origin Cache Storage with byte progress. During an explicit resumed installation, existing matching cache entries are SHA-256 rehashed before reuse; corrupted or size-mismatched entries are re-downloaded only because the user requested an install. SHA-256 engine/read failures leave previously cached bytes unchanged and report an error instead of evicting data. This additional retry check uses bounded-memory incremental Blob hashing for MediaPipe (~295 MB weights) rather than a second model-sized ArrayBuffer. ONNX and dictionary assets still use WebCrypto with one asset buffer at a time. It discards any asset with an unexpected received length, reuses existing assets only after checksum verification on a requested retry, and supports removal. The extension's own origin is required for cache keys; no large files are written to browser.storage.sync or local. MediaPipe and ONNX executable JavaScript and WASM binaries must be packaged through build.js separately, not fetched through this data store.

Cache Storage is owned by the extension origin but Cache.put requires an HTTP(S) request key. Stored assets use synthetic https://kokoro-model-cache.invalid/ keys; that reserved host is never contacted. The bytes are fetched only from manifest-pinned model asset URLs. Request metadata records the expected hash/size, while the initial download uses the browser's Fetch SRI check. Since Fetch SRI may buffer before exposing a response, this first-stage progress counter is not guaranteed to reflect network transfer in real time. Model manager UI must not label it a real-time percentage until verified in Chrome and Firefox; #55 still requires a tested streaming verification/download strategy. Cache status should not be treated as proof of intact bytes after external corruption. The small optional English pronunciation dictionary is now checked against its pinned SHA-256 before parsing for ONNX speech, without network requests or implicit deletion. Failed verification asks the user to repair it explicitly. ONNX now also verifies the already-loaded model and voice buffers against pinned SHA-256 digests before creating a runtime session, without a second cache read or automatic repair. Verification happens on initialization, not on every synthesized sentence. MediaPipe now verifies the full pinned SHA-256 of its cached model Blob before initializing the official SDK, using bounded-memory incremental hashing rather than materializing a second ~295-MB ArrayBuffer. A mismatched hash fails closed without auto-download or eviction. The same streaming hash is now also used for MediaPipe's explicit Verify cached data action and install retries, with cancellation support and no additional model-sized arrayBuffer. Cancelling a stalled cached Blob stream actively terminates its pending read, rather than waiting indefinitely for another storage chunk. It also releases the verifier's reader lock without waiting for a misbehaving source's never-settling cancellation promise; an underlying cleanup error cannot replace the original cancellation result. No existing cached entry is evicted on cancellation. This standard SHA-256 implementation is tested against Node's independent crypto hashes and fixed known-answer vectors; real-browser performance and packaged-browser acceptance remain outstanding.

Asset paths reject empty, '.' and '..' segments to prevent normalized cache-key collisions. Paths and URLs must match exactly, including the official repository identity and immutable revision. The only permitted file extensions are model/voice/text data types; no remotely downloaded .js/.wasm/executable assets.

The manager exposes an explicit removeUnreferenced(retainedManifests) operation for post-upgrade cleanup: callers pass *all* selected/installed model manifests to retain and the cache enumerates its own model-data keys, deleting older revisions/variants not listed. This never removes unrelated Cache Storage entries, and is not invoked automatically by normal installation. The benchmark page now offers a confirmed **Remove obsolete model cache files** action. It passes every pinned MediaPipe, ONNX, and dictionary manifest from the current catalog to removeUnreferenced(), keeping both installed and partially downloaded supported variants. It only removes older/unlisted model-data keys after the user confirms, under the exclusive cross-context cache lock; it does not run on page load, fetch data, or delete other Cache Storage entries. Removing a currently offered variant remains a separate per-model action.

The model-data store must be instantiated only from a suitable extension-origin page/worker that exposes Cache Storage, Fetch, Response and TransformStream; this module doesn't create such a context. Tests use small fake data; no production weights or executable code are downloaded by CI.

Before enabling any Download button in #58 or #61:
- Confirm official ONNX and MediaPipe model commits, checksums, voice/config/phonemizer assets and exact sizes against upstream. Do not substitute the approximate 86/92/295/326 MB model-only figures for actual total bytes.
- Add a registry containing only supported model/delegate configurations validated by #53, and track installed revisions/variants so removeUnreferenced is called with the correct retain list.
- Validate Firefox and Chrome installed extension CORS/Cache Storage/SRI behavior, Browser quota, cache eviction, failed/cancelled/retried downloads, network disconnect and restart.
- Verify that browser Fetch's SRI is enforced on downloaded opaque redirect chains, and that Cache Storage retains the response after restarts. Treat absence of a readable CORS response as an explicit error.
- Add a shared in-flight-download lock and resumable partial-file storage only if that proves useful; current stage retries the whole failed asset.
- Keep runtime code local and never transmit speech input to model hosts.

Original implementation; no code copied from third-party Kokoro extensions.
